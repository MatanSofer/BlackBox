# BlackBox — Database Documentation

---

## 1. Overview

BlackBox uses **SQLDelight** for type-safe database access across KMP, with **SQLCipher** for encryption on Android. The database stores all collected records, derived events, daily summaries, known places, and user settings.

**Key design principles:**
- Denormalized where speed matters (LocationRecord has its own table for geo-queries)
- JSON columns for flexible, collector-specific data (avoids schema changes per collector)
- Pre-computed daily summaries for fast retrieval
- Indexed on timestamp for all time-range queries
- Cascade deletes to maintain referential integrity

## 2. Complete Schema

### 2.1 BlackBoxRecord — Core Record Table

Every data point from every collector goes here. This is the "flight recorder tape."

```sql
-- The master table for all collected data points.
-- Each row represents a single collection event from a specific collector.
CREATE TABLE BlackBoxRecord (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    -- Unix epoch milliseconds when this data was captured
    timestamp INTEGER NOT NULL,
    -- Which collector produced this record
    -- Values: LOCATION, ACTIVITY, WIFI, APP_USAGE, SCREEN_STATE,
    --         AUDIO_LEVEL, BATTERY, CONNECTIVITY, BAROMETER, LIGHT
    collector_type TEXT NOT NULL,
    -- JSON-encoded collector-specific data payload
    -- Structure varies by collector_type (see Section 3)
    data_json TEXT NOT NULL,
    -- Confidence score for this data point (0.0 to 1.0)
    -- Lower when GPS accuracy is poor, sensor is unreliable, etc.
    accuracy_score REAL NOT NULL DEFAULT 1.0,
    -- Groups records collected in the same collection cycle
    -- Format: UUID v4 string
    session_id TEXT NOT NULL,
    -- When this row was inserted into the database
    created_at INTEGER NOT NULL
);

-- Primary query pattern: get records by time range
CREATE INDEX idx_record_timestamp ON BlackBoxRecord(timestamp);
-- Query pattern: get records by type within time range
CREATE INDEX idx_record_collector_time ON BlackBoxRecord(collector_type, timestamp);
-- Query pattern: group records by collection session
CREATE INDEX idx_record_session ON BlackBoxRecord(session_id);
-- Cleanup pattern: delete old records
CREATE INDEX idx_record_created ON BlackBoxRecord(created_at);
```

### 2.2 LocationRecord — Denormalized Location Data

Separate table for fast geo-queries. Every location collection also creates a BlackBoxRecord.

```sql
-- Denormalized location data for fast spatial and temporal queries.
-- Each row corresponds to a BlackBoxRecord with collector_type = 'LOCATION'.
CREATE TABLE LocationRecord (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    -- References the parent BlackBoxRecord
    record_id INTEGER NOT NULL REFERENCES BlackBoxRecord(id) ON DELETE CASCADE,
    -- WGS84 coordinates
    latitude REAL NOT NULL,
    longitude REAL NOT NULL,
    -- Meters above sea level (nullable — not always available)
    altitude REAL,
    -- GPS accuracy radius in meters
    accuracy_meters REAL,
    -- Speed in meters per second (nullable — 0 when stationary)
    speed REAL,
    -- Compass bearing in degrees (0-360, nullable)
    bearing REAL,
    -- How this location was determined
    -- Values: GPS, WIFI, CELL, FUSED, NETWORK
    source TEXT NOT NULL,
    -- Duplicate of BlackBoxRecord.timestamp for query efficiency
    timestamp INTEGER NOT NULL
);

-- Time-range queries on location
CREATE INDEX idx_location_timestamp ON LocationRecord(timestamp);
-- Spatial queries (approximate, for bounding box pre-filter)
CREATE INDEX idx_location_coords ON LocationRecord(latitude, longitude);
-- Join back to parent record
CREATE INDEX idx_location_record_id ON LocationRecord(record_id);
```

### 2.3 DailySummary — Pre-Computed Day Aggregations

Generated once per day (end-of-day job). Provides fast answers to common queries.

```sql
-- Pre-computed summary for each day. Generated by DailySummaryWorker.
-- Provides fast access to common queries without scanning raw records.
CREATE TABLE DailySummary (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    -- Date string in ISO format: "2026-02-14"
    date TEXT NOT NULL UNIQUE,
    -- Step counter total for the day
    total_steps INTEGER NOT NULL DEFAULT 0,
    -- Total distance traveled in meters (derived from location points)
    total_distance_meters REAL NOT NULL DEFAULT 0.0,
    -- Minutes spent at the "Home" known place
    time_at_home_minutes INTEGER NOT NULL DEFAULT 0,
    -- Minutes spent at the "Work" known place
    time_at_work_minutes INTEGER NOT NULL DEFAULT 0,
    -- Minutes spent in transit (DRIVING, ON_BICYCLE, IN_VEHICLE activities)
    time_in_transit_minutes INTEGER NOT NULL DEFAULT 0,
    -- Number of times screen was turned on
    screen_on_count INTEGER NOT NULL DEFAULT 0,
    -- Total minutes screen was on
    total_screen_time_minutes INTEGER NOT NULL DEFAULT 0,
    -- JSON array of top apps by usage time
    -- Format: [{"package": "com.whatsapp", "name": "WhatsApp", "minutes": 45}, ...]
    most_used_apps TEXT NOT NULL DEFAULT '[]',
    -- JSON array of visited locations with durations
    -- Format: [{"place_id": 1, "name": "Office", "lat": 32.0, "lng": 34.7, "minutes": 480, "arrived": 1234, "departed": 5678}, ...]
    locations_visited TEXT NOT NULL DEFAULT '[]',
    -- JSON object mapping activity types to minutes
    -- Format: {"STILL": 480, "WALKING": 60, "DRIVING": 35, "RUNNING": 0, ...}
    activity_breakdown TEXT NOT NULL DEFAULT '{}',
    -- Average ambient noise level for the day in dB
    noise_avg_db REAL,
    -- Timestamp of first screen unlock (epoch ms)
    first_screen_on INTEGER,
    -- Timestamp of last screen off before sleep (epoch ms)
    last_screen_off INTEGER,
    -- Estimated sleep start timestamp (epoch ms)
    -- Derived from: screen off + still + dark + at home
    sleep_start_estimate INTEGER,
    -- Estimated sleep end timestamp (epoch ms)
    -- Derived from: first movement + screen on after long still period
    sleep_end_estimate INTEGER,
    -- Hash of all raw records for this day (for integrity chain)
    -- SHA-256 hex string
    day_hash TEXT,
    -- Hash of the previous day's day_hash (chain integrity)
    previous_day_hash TEXT,
    -- AI-generated natural language summary of the day
    -- Example: "You spent most of the day at the office (7h). Left for lunch at Aroma (45min). 8,421 steps. Bed at 11:30pm."
    summary_text TEXT,
    -- When this summary was generated/last updated
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);

CREATE INDEX idx_summary_date ON DailySummary(date);
```

### 2.4 KnownPlace — Learned Locations

Auto-detected or user-defined meaningful places.

```sql
-- A meaningful location that the user visits regularly.
-- Auto-detected by clustering frequent GPS coordinates, or manually created by user.
CREATE TABLE KnownPlace (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    -- Display name: "Home", "Office", "Gym", or auto-generated "Place #7"
    name TEXT NOT NULL,
    -- Center coordinates of this place
    latitude REAL NOT NULL,
    longitude REAL NOT NULL,
    -- Radius in meters that defines "at this place" (default 100m)
    radius_meters REAL NOT NULL DEFAULT 100.0,
    -- JSON array of WiFi BSSIDs associated with this place
    -- Used for indoor location matching
    -- Format: ["aa:bb:cc:dd:ee:ff", "11:22:33:44:55:66"]
    wifi_fingerprint TEXT,
    -- Category for grouping and display
    -- Values: HOME, WORK, GYM, RESTAURANT, SHOPPING, SCHOOL,
    --         MEDICAL, ENTERTAINMENT, TRANSIT, OTHER
    category TEXT NOT NULL DEFAULT 'OTHER',
    -- How many times the user has visited this place
    visit_count INTEGER NOT NULL DEFAULT 0,
    -- Total time spent at this place in minutes (all-time)
    total_time_minutes INTEGER NOT NULL DEFAULT 0,
    -- Timestamp of first detected visit (epoch ms)
    first_visit INTEGER,
    -- Timestamp of most recent visit (epoch ms)
    last_visit INTEGER,
    -- 1 = auto-detected by clustering algorithm
    -- 0 = manually created or named by user
    is_auto_detected INTEGER NOT NULL DEFAULT 1,
    -- Whether this place is hidden from the UI (user chose to ignore it)
    is_hidden INTEGER NOT NULL DEFAULT 0,
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);

CREATE INDEX idx_place_coords ON KnownPlace(latitude, longitude);
CREATE INDEX idx_place_category ON KnownPlace(category);
```

### 2.5 DerivedEvent — Significant Events

Events derived from raw data analysis (arrivals, departures, sleep, etc.).

```sql
-- A significant event derived from analyzing raw data.
-- Examples: arrived at office, departed home, started driving, sleep detected.
CREATE TABLE DerivedEvent (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    -- When this event occurred (epoch ms)
    timestamp INTEGER NOT NULL,
    -- Event type identifier
    -- Values: ARRIVED, DEPARTED, STARTED_DRIVING, STOPPED_DRIVING,
    --         STARTED_WALKING, SLEEP_START, SLEEP_END, PHONE_PICKUP,
    --         ENTERED_TRANSIT, EXITED_TRANSIT, SIGNIFICANT_MOVEMENT,
    --         LONG_STATIONARY, ANOMALOUS_ACTIVITY
    event_type TEXT NOT NULL,
    -- Human-readable description: "Arrived at Office", "Started driving"
    description TEXT NOT NULL,
    -- Optional reference to the place involved in this event
    place_id INTEGER REFERENCES KnownPlace(id) ON DELETE SET NULL,
    -- JSON object with additional event-specific context
    -- ARRIVED/DEPARTED: {"from_place_id": 1, "travel_duration_min": 35, "travel_mode": "DRIVING"}
    -- SLEEP_START/END: {"confidence": 0.92, "signals": ["screen_off", "still", "dark", "home"]}
    -- ANOMALOUS_ACTIVITY: {"reason": "phone_used_during_sleep", "duration_min": 15}
    metadata_json TEXT,
    -- Confidence that this event actually occurred (0.0 to 1.0)
    -- Based on how many independent data sources corroborate it
    confidence REAL NOT NULL DEFAULT 1.0,
    created_at INTEGER NOT NULL
);

CREATE INDEX idx_event_timestamp ON DerivedEvent(timestamp);
CREATE INDEX idx_event_type_time ON DerivedEvent(event_type, timestamp);
CREATE INDEX idx_event_place ON DerivedEvent(place_id);
```

### 2.6 CollectorSetting — User Preferences Per Collector

```sql
-- User's enable/disable and configuration preferences for each collector.
CREATE TABLE CollectorSetting (

    -- JSON object with collector-specific configuration

    -- AUDIO_LEVEL: {"sample_duration_seconds": 3}
    custom_config_json TEXT,
    updated_at INTEGER NOT NULL
);
```

## 4. Common SQLDelight Queries

### 4.1 Record Queries

```sql
-- Get all records in a time range for a specific collector
getRecordsByTypeInRange:
SELECT * FROM BlackBoxRecord
WHERE collector_type = :collectorType
  AND timestamp BETWEEN :startTime AND :endTime
ORDER BY timestamp ASC;

-- Get all records in a time range (all collectors)
getAllRecordsInRange:
SELECT * FROM BlackBoxRecord
WHERE timestamp BETWEEN :startTime AND :endTime
ORDER BY timestamp ASC;

-- Count records by collector type
countByCollector:
SELECT collector_type, COUNT(*) AS record_count
FROM BlackBoxRecord
GROUP BY collector_type;

-- Delete records older than retention date
deleteOlderThan:
DELETE FROM BlackBoxRecord
WHERE created_at < :cutoffTimestamp;

-- Get total storage estimate (approximate)
getTotalRecordCount:
SELECT COUNT(*) FROM BlackBoxRecord;
```

### 4.2 Location Queries

```sql
-- Get locations in time range
getLocationsInRange:
SELECT * FROM LocationRecord
WHERE timestamp BETWEEN :startTime AND :endTime
ORDER BY timestamp ASC;

-- Get the closest location to a specific timestamp
getLocationAt:
SELECT * FROM LocationRecord
WHERE timestamp BETWEEN (:targetTime - :toleranceMs) AND (:targetTime + :toleranceMs)
ORDER BY ABS(timestamp - :targetTime) ASC
LIMIT 1;

-- Get last known location
getLastKnownLocation:
SELECT * FROM LocationRecord
ORDER BY timestamp DESC
LIMIT 1;

-- Get locations within a bounding box (for map view)
getLocationsInBoundingBox:
SELECT * FROM LocationRecord
WHERE latitude BETWEEN :minLat AND :maxLat
  AND longitude BETWEEN :minLng AND :maxLng
  AND timestamp BETWEEN :startTime AND :endTime
ORDER BY timestamp ASC;

-- Get distinct location clusters for a day (for place detection)
getLocationClustersForDay:
SELECT
    ROUND(latitude, 3) AS cluster_lat,
    ROUND(longitude, 3) AS cluster_lng,
    COUNT(*) AS point_count,
    MIN(timestamp) AS first_seen,
    MAX(timestamp) AS last_seen,
    AVG(accuracy_meters) AS avg_accuracy
FROM LocationRecord
WHERE timestamp BETWEEN :dayStart AND :dayEnd
GROUP BY cluster_lat, cluster_lng
HAVING point_count >= 3
ORDER BY point_count DESC;
```

### 4.3 Daily Summary Queries

```sql
-- Get summary for a specific date
getSummaryForDate:
SELECT * FROM DailySummary
WHERE date = :dateString;

-- Get summaries for a date range
getSummariesInRange:
SELECT * FROM DailySummary
WHERE date BETWEEN :startDate AND :endDate
ORDER BY date ASC;

-- Get average wake time over N days
getAverageWakeTime:
SELECT AVG(sleep_end_estimate) AS avg_wake_time
FROM DailySummary
WHERE sleep_end_estimate IS NOT NULL
  AND date BETWEEN :startDate AND :endDate;

-- Get step count trend
getStepTrend:
SELECT date, total_steps
FROM DailySummary
WHERE date BETWEEN :startDate AND :endDate
ORDER BY date ASC;

-- Get screen time trend
getScreenTimeTrend:
SELECT date, total_screen_time_minutes, screen_on_count
FROM DailySummary
WHERE date BETWEEN :startDate AND :endDate
ORDER BY date ASC;
```

### 4.4 Known Place Queries

```sql
-- Get all visible known places
getAllPlaces:
SELECT * FROM KnownPlace
WHERE is_hidden = 0
ORDER BY visit_count DESC;

-- Find the nearest known place to coordinates
findNearestPlace:
SELECT *,
    (latitude - :lat) * (latitude - :lat) +
    (longitude - :lng) * (longitude - :lng) AS distance_squared
FROM KnownPlace
WHERE is_hidden = 0
ORDER BY distance_squared ASC
LIMIT 1;

-- Get places by category
getPlacesByCategory:
SELECT * FROM KnownPlace
WHERE category = :category AND is_hidden = 0
ORDER BY visit_count DESC;

-- Update visit stats
incrementVisitCount:
UPDATE KnownPlace
SET visit_count = visit_count + 1,
    last_visit = :visitTimestamp,
    updated_at = :now
WHERE id = :placeId;
```

### 4.5 Derived Event Queries

```sql
-- Get events in time range
getEventsInRange:
SELECT de.*, kp.name AS place_name, kp.category AS place_category
FROM DerivedEvent de
LEFT JOIN KnownPlace kp ON de.place_id = kp.id
WHERE de.timestamp BETWEEN :startTime AND :endTime
ORDER BY de.timestamp ASC;

-- Get arrival/departure events for a specific place
getPlaceEvents:
SELECT * FROM DerivedEvent
WHERE place_id = :placeId
  AND event_type IN ('ARRIVED', 'DEPARTED')
ORDER BY timestamp DESC
LIMIT :limit;

-- Get latest event of a specific type
getLatestEventOfType:
SELECT de.*, kp.name AS place_name
FROM DerivedEvent de
LEFT JOIN KnownPlace kp ON de.place_id = kp.id
WHERE de.event_type = :eventType
ORDER BY de.timestamp DESC
LIMIT 1;

-- Get sleep events for date range
getSleepEvents:
SELECT * FROM DerivedEvent
WHERE event_type IN ('SLEEP_START', 'SLEEP_END')
  AND timestamp BETWEEN :startTime AND :endTime
ORDER BY timestamp ASC;
```

### 4.6 Settings Queries

```sql
-- Get all collector settings
getAllSettings:
SELECT * FROM CollectorSetting;

-- Get setting for specific collector
getSettingForCollector:
SELECT * FROM CollectorSetting
WHERE collector_type = :collectorType;

-- Update enabled state
setCollectorEnabled:
UPDATE CollectorSetting
SET is_enabled = :enabled, updated_at = :now
WHERE collector_type = :collectorType;

-- Update collection interval
setCollectionInterval:
UPDATE CollectorSetting
SET collection_interval_ms = :intervalMs, updated_at = :now

```

### 4.7 Recent Query Queries

```sql
-- Get recent queries (most recent first)
getRecentQueries:
SELECT * FROM RecentQuery
ORDER BY executed_at DESC
LIMIT :limit;

-- Insert new query
insertQuery:
INSERT INTO RecentQuery (query_text, intent_type, executed_at)
VALUES (:queryText, :intentType, :executedAt);

-- Delete old queries (keep last N)
cleanupOldQueries:
DELETE FROM RecentQuery
WHERE id NOT IN (
    SELECT id FROM RecentQuery ORDER BY executed_at DESC LIMIT :keepCount
);
```

## 6. Data Retention & Cleanup

### 6.1 Cleanup Strategy

The `CleanupWorker` runs daily at 3:00 AM and performs:

1. **Delete raw records** older than the retention period (default: 365 days)
2. **Keep daily summaries** indefinitely (they're tiny ~1KB each)
3. **Keep derived events** indefinitely (also tiny)
4. **Keep known places** indefinitely
5. **Vacuum the database** after large deletions to reclaim space
6. **Trim recent queries** to the last 50

### 6.2 Retention Configuration

```kotlin
enum class RetentionPeriod(val days: Int) {
    THREE_MONTHS(90),
    SIX_MONTHS(180),
    ONE_YEAR(365),      // default
    TWO_YEARS(730),
    UNLIMITED(-1)
}
```

## 7. Migration Strategy

SQLDelight migrations are numbered files in `shared/data/database/migrations/`:

```
migrations/
├── 1.sqm    -- Initial schema
├── 2.sqm    -- Add RecentQuery table
├── 3.sqm    -- Add AppInfo table
└── ...
```

**Migration rules:**
- Never modify existing columns — add new ones
- Always provide default values for new columns
- Test migrations with pre-populated test databases
- Document each migration in this file
